## Critical gaps

### 1. Live UI proof is still missing

**CRITICAL GAP:** The project has backend state projection and a timeline component, but this run did not produce a captured local browser proof where a real `video-maker` LangGraph thread advances the visible timeline through Source Intake and Script checkpoint.

**Impact:** The product may be technically correct while still failing the operator demo: users judge this project through the chat UI, not only through CLI smokes.

**Recommendation:** Add a documented `docs/live-ui-demo.md` or `scripts/smoke_ui_thread.*` path that starts backend + UI, creates/opens a thread, runs the golden prompt to the script checkpoint, and captures evidence that `videoMaker.milestones` reaches expected statuses in the UI.

### 2. Production UI build is still unreliable on Windows

**CRITICAL GAP:** `pnpm ui:build` still fails with `Error: spawn EPERM` after a successful Next compile and TypeScript phase. The previously documented local-node workaround is insufficient in this current environment.

**Impact:** Local/CI confidence remains ambiguous: a stakeholder can run dev UI, but the production build gate is not green.

**Recommendation:** Isolate whether the failing spawn is Next telemetry/typegen/lint worker, Node process spawning, antivirus/temp ACL, or pnpm lifecycle. Keep the current workaround only if it is reproducibly green; otherwise document `ui:dev` as demo-only and mark `ui:build` as blocked until fixed.

## Scope proposals

### 1A. Accepted — make live UI proof the next P0

Create a repeatable proof that the web UI renders native `video_maker` state from an actual LangGraph thread. This should be the next CEO review target because the backend proof is now adequate.

### 1B. Accepted — keep the three-tier golden ladder

Do not collapse `golden:script`, `golden:render`, and `golden:playable`. Their separation is productively honest: script checkpoint, pipeline plumbing, and playable media proof answer different questions.

### 1C. Deferred — require Remotion renderer as the default golden proof

The `ffmpeg` playable proof is acceptable for now because it verifies real media packaging and ratification. Requiring `--renderer remotion --install` as default would add environment fragility before the UI demo is proven.

### 1D. Rejected — claim publish-ready autonomy

Do not market this as “autonomous publish-ready video generation.” The honest promise is gated production with human approval and advisory publish readiness.
