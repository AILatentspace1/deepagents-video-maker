## Architecture review

### 1. UI timeline state has no backend producer

**Finding:** The UI reads `stream.values.video_maker` in `web-ui/src/app/hooks/useChat.ts:26` and `web-ui/src/app/hooks/useChat.ts:168`, and `VideoProductionTimeline` expects `videoMaker.milestones`, `currentBlocker`, `nextActions`, and `publishReadiness` at `web-ui/src/app/components/VideoProductionTimeline.tsx:68-87`. However, repo search found no Python or LangGraph state writer for `video_maker`; native tools only save `state.yaml` and return per-tool payloads (`src/deepagents_video_maker/langchain_tools.py:95`, `:135`, `:240`, `:308`, `:368`).

**Risk:** Operators may see a polished timeline shell with artifacts but all milestones stuck at fallback `pending`, no blocker text, and no publish-readiness summary, even after the underlying run has advanced in `state.yaml`.

**Recommendation:** Add a small state projection function, for example `build_video_maker_ui_state(output_dir)`, that maps `VideoMakerState` + known artifact paths + publish-readiness JSON into the `video_maker` state shape. Call it from every milestone tool return/update path, and add a UI/backend contract test that asserts completed golden-demo milestones render as completed.

### 2. Build verification is partially blocked by Windows runtime, not TypeScript

**Finding:** `pnpm --filter deepagent-video-maker-ui build` compiled successfully and completed TypeScript, then failed with `Error: spawn EPERM`. This looks environment/toolchain-related rather than a source compile error, but it means the production Next build was not fully proven in this run.

**Risk:** A future CI or developer machine may expose a post-TypeScript Next build issue that local lint does not catch. Conversely, this Windows EPERM can create false alarms during automated review.

**Recommendation:** Keep `TEMP=C:\tmp`/`TMP=C:\tmp` for pnpm commands, and add either a documented Windows workaround or a CI-side `pnpm --filter deepagent-video-maker-ui build` check on a clean runner.
