### 1. Source Intake can silently accept invalid local inputs

`source_flow.py` falls back to a synthetic `manual` item when no files are found; `local-file` can record a nonexistent path with `size_bytes: unknown`; `ratify_source_manifest()` only checks `- path:` for non-websearch modes. Missing folders/files can therefore pass as usable sources.

**Recommendation:** fail fast for missing/empty `folder` and missing `local-file`; add path-existence checks to ratify.

**Priority:** P1 / critical gap.

### 2. `websearch` is documented/default but not implemented as Source Intake

`VideoMakerGoal.source` defaults to `websearch`, and the contract requires URL manifest items. Runtime `_manifest_items()` creates no websearch items, the active subagent list has only `scriptwriter`, and ratify then blocks because no URL exists.

**Recommendation:** either implement URL/snippet-producing websearch intake or remove `websearch` as a default supported source until it exists.

**Priority:** P1 / critical gap.

### 3. `state.yaml` schema drifts from `workflow-contract.md`

The contract documents `updated_at`, `current_step`, nested `steps`, and `artifacts`; runtime writes a milestone-list schema and `load_state_yaml()` drops todos/ratify/artifacts details.

**Recommendation:** pick one state contract and make docs, serializer, loader, and tests agree.

**Priority:** P2.

### 4. Script ratify is weaker than the v2 contract

The contract calls for checks such as max consecutive scene types and source-grounded `data_card` semantics. Current ratify checks scene count range and only a subset of per-scene fields.

**Recommendation:** add tests and ratify rules for repeated scene types, `data_card` grounding fields, and narration/data semantic separation.

**Priority:** P1/P2.

### 5. Harness/eval references are stale

`package.json` still exposes `test:evals`, and `harness/video-maker-minimal.toml` points at deleted v1/eval paths such as `../skills/video-maker/agents/scriptwriter.md`, `scripts/video_to_golden.py`, and `tests/evals/*`.

**Recommendation:** migrate harness/evals to `skills/video-maker-v2/agents/scriptwriter.md` and v2 tests, or remove disabled scripts until rebuilt.

**Priority:** P1.

### 6. Build/render stages are modeled but not executable through native tools

`session.py` defines `build_scenes` and `render_package`, and the v2 skill describes end-to-end audio/build/render. `build_langchain_tools()` exposes only Source Intake and Script tools.

**Recommendation:** keep README honest about the current runnable path; add explicit audio/build/render/package tools before claiming full e2e support.

**Priority:** P2 now; P1 before e2e claims.
