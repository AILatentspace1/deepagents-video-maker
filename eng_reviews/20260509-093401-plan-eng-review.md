## Architecture review

### 1. UI production build remains blocked after the wrapper

**Finding:** `package.json` maps `ui:build` to `node scripts/build-ui.mjs`, and the wrapper invokes the local Next binary with `spawnSync(process.execPath, [nextBin, "build"], ...)`. On this run, even with `TEMP=C:\tmp`, `TMP=C:\tmp`, and `UV_CACHE_DIR` set, `pnpm ui:build` compiled and typechecked, then failed with `Error: spawn EPERM`.

**Evidence:** `E:\workspace\deepagents-video-maker\package.json:14`, `E:\workspace\deepagents-video-maker\scripts\build-ui.mjs:16-24`, `E:\workspace\deepagents-video-maker\docs\golden-demo.md:149-166`.

**Risk:** A release path that includes the web UI cannot be marked production-build verified. The wrapper can create false confidence because docs say it avoids intermittent `spawn EPERM`, while current evidence shows it still fails.

**Recommendation:** Treat this as an open build-environment blocker, not resolved. Add a CI/Linux clean-runner build check or a Windows-specific build path that avoids the failing post-TypeScript spawn; update the previous review/result text after the fix is proven.

### 2. New pnpm smoke commands require env bootstrapping that docs do not consistently enforce

**Finding:** `docs/golden-demo.md` documents `pnpm golden:playable` and `pnpm ui:build` as normal Quick Verification commands. In this workspace, raw `pnpm golden:playable` failed before Python ran due `C:\Users\ADMINI~1` temp access. `pnpm harness:validate` also failed unless `UV_CACHE_DIR` was set to the repo-local cache. The doc has a temp workaround, but it appears after the command list and does not apply the full `TEMP`/`TMP`/`UV_CACHE_DIR` triple to all pnpm-driven smoke commands.

**Evidence:** `E:\workspace\deepagents-video-maker\docs\golden-demo.md:67`, `E:\workspace\deepagents-video-maker\docs\golden-demo.md:147-157`, `E:\workspace\deepagents-video-maker\package.json:9-14`.

**Risk:** Operators following the documented commands may hit machine-local permission errors and misdiagnose them as product regressions. Automation can also flip between pass/fail depending on inherited environment.

**Recommendation:** Either wrap pnpm scripts so they set the known-good env consistently, or promote the full Windows-safe command block before Quick Verification. If keeping raw pnpm commands, state that Windows automation must set `TEMP=C:\tmp`, `TMP=C:\tmp`, and `UV_CACHE_DIR=E:\workspace\deepagents-video-maker\.uv-cache`.

### 3. Source-less requests now depend on Tavily availability by default

**Finding:** `derive_video_params()` changes `source=manual` with no source path into `source=websearch`. That is tested and probably intentional, but it changes the default path from offline/manual to network/provider-dependent.

**Evidence:** `E:\workspace\deepagents-video-maker\src\deepagents_video_maker\params.py:68-77`, `E:\workspace\deepagents-video-maker\src\deepagents_video_maker\source_flow.py:151-157`, `E:\workspace\deepagents-video-maker\tests\deepagents_video_maker\test_params.py`, `E:\workspace\deepagents-video-maker\tests\deepagents_video_maker\test_research_flow.py`.

**Risk:** A plain request like `topic=AI Agent` will block Source Intake without `TAVILY_API_KEY`. That is acceptable for source quality, but it should be explicit in operator docs and UI copy so users do not expect a manual/topic-only flow.

**Recommendation:** Keep the behavior if web sourcing is the desired canonical default, but surface it in docs/UI: “No source path means websearch; configure `TAVILY_API_KEY` or specify `source=manual`/`source_folder`.”
